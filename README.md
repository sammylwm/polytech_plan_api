# Polytech Plan API

Django API для расписания учебных групп, дедлайнов и заданий на сессию. Расписание загружается из `rasp.dmami.ru`, дедлайны и задания хранятся в PostgreSQL.

## Запуск

Если файла `.env` ещё нет, создайте его из `template.env`. Заполните параметры PostgreSQL. Для распознавания дедлайнов и сравнения похожих заданий укажите `AI_KEY` с ключом DeepSeek.

```bash
test -f .env || cp template.env .env
```

После настройки создайте общую сеть `poly-shared`, если она ещё не существует,
и запустите production-контейнеры.

```bash
docker network inspect poly-shared >/dev/null 2>&1 || docker network create poly-shared
docker compose up -d --build
```

Контейнер запускает Django через uWSGI на порту `8000` и применяет миграции при старте.
Посмотреть состояние и логи можно командами:

```bash
docker compose ps
docker compose logs -f api
```

API доступен на `http://localhost:8000`. Для внешнего production-сервера замените
`DJANGO_ALLOWED_HOSTS` в `.env` на домен API и поставьте перед контейнером HTTPS
reverse proxy (например, Nginx). Чтобы остановить сервисы, выполните
`docker compose down`; данные PostgreSQL и загруженные файлы останутся в volumes.

- Swagger UI доступен по `/docs/swagger/`.
- Схема OpenAPI доступна по `/docs/openapi.json/`.
- Панель Django доступна по `/admin/`.

## Маршруты API

| Метод | Путь | Назначение | Успешный ответ |
| --- | --- | --- | --- |
| GET | `/api/schedule/` | Занятия и дедлайны группы за период | `200` |
| GET | `/api/deadline/` | Дедлайны группы за период | `200` |
| POST | `/api/deadline/` | Ручное создание дедлайна | `201` |
| GET | `/api/deadline/attachments/<uuid>/` | Скачать вложение по публичной ссылке | `200` |
| DELETE | `/api/deadline/` | Удаление дедлайна по ID | `200` |
| POST | `/api/deadline/parse/` | Распознавание дедлайна из текста | `200` |
| POST | `/api/deadline/confirm/` | Подтверждение и сохранение дедлайна | `200` |
| GET | `/api/session-task/` | Задания группы на семестр | `200` |
| POST | `/api/session-task/` | Добавление задания на сессию | `201` |
| DELETE | `/api/session-task/` | Удаление задания на сессию по ID | `200` |

Номер группы состоит из трёх цифр, дефиса и ещё трёх цифр, например `261-329`. Все даты в API имеют формат `YYYY-MM-DD`. POST-запросы принимают JSON с заголовком `Content-Type: application/json`. Для создания дедлайна с файлами используйте `multipart/form-data`. Ошибки валидации параметров и тела запроса возвращаются с кодом `400` и массивом ошибок в `detail`. Ошибки операций ниже содержат текст в `detail`.

## Расписание и выборка за период

`GET /api/schedule/?group=261-329&start=2026-11-19&end=2026-11-21`

| Параметр | Обязательный | Значение |
| --- | --- | --- |
| `group` | Да | Номер группы |
| `start` | Нет | Первый день периода. По умолчанию текущая дата сервера |
| `end` | Нет | Последний день периода. По умолчанию текущая дата сервера |

Обе границы включены. `end` должен быть не раньше `start`. Эти параметры также используются в `GET /api/deadline/`.

```json
{
  "lessons": [
    {
      "subject": "Физика",
      "pair": 2,
      "start": "10:40",
      "end": "12:10",
      "teacher": "Иванов И. И.",
      "rooms": ["Пр2302"],
      "type": "Лекция",
      "weekday": 4,
      "date_from": "2026-09-01",
      "date_to": "2026-12-31",
      "date": "2026-11-19",
      "link": null,
      "pair_time": {"start": "10:40", "end": "12:10"}
    }
  ],
  "deadlines": [
    {
      "id": 42,
      "date": "2026-11-20",
      "subject": "Физика",
      "deadline": "Сдать отчёт по лабораторной работе",
      "group": "261-329",
      "attachments": []
    }
  ]
}
```

Занятия сортируются по дате и номеру пары. `weekday` принимает значения от 1 (понедельник) до 7 (воскресенье) или `null` для записи, заданной конкретной датой. `date_from` и `date_to` задают период действия занятия и могут быть `null`. `link` содержит ссылку на занятие или `null`. При отсутствии данных `teacher` и `type` содержат пустую строку, а `rooms` содержит пустой массив.

`pair_time` содержит время начала и окончания по номеру `pair` из `PAIR_TIMES`. Поля занятия `start` и `end` содержат те же значения для совместимости.

| Пара | Начало | Окончание |
| --- | --- | --- |
| 1 | 09:00 | 10:30 |
| 2 | 10:40 | 12:10 |
| 3 | 12:20 | 13:50 |
| 4 | 14:30 | 16:00 |
| 5 | 16:10 | 17:40 |
| 6 | 17:50 | 19:20 |
| 7 | 19:30 | 21:00 |

`GET /api/deadline/?group=261-329&start=2026-11-19&end=2026-11-21` возвращает массив объектов в том же формате, что и `deadlines` в расписании. Записи отсортированы по дате, затем по ID. При отсутствии записей возвращается `[]`.

## Ручное добавление

`POST /api/deadline/` принимает готовые данные и сразу записывает дедлайн в базу без вызова DeepSeek.

```json
{
  "group": "261-329",
  "date": "2026-11-20",
  "subject": "Физика",
  "deadline": "Сдать отчёт по лабораторной работе"
}
```

При успехе возвращается `201` и объект дедлайна с `id`. Если запись с той же группой, датой, предметом и текстом уже существует, возвращается `409` с сообщением «Такая запись уже существует». Схема также принимает необязательные `start` и `end` и проверяет их порядок. Дата записи берётся из `date`.

## Вложения

Передайте поля дедлайна и до пяти файлов в одном запросе. Для каждого файла повторите поле `attachments`.

В Swagger откройте `POST /api/deadline/confirm/` для подтверждения после распознавания или `POST /api/deadline/` для ручного создания. Нажмите **Try it out** и в разделе **Request body** переключите тип запроса на `multipart/form-data`. В поле `attachments` нажмите **Add string item**, чтобы добавить выбор файла. Повторите для каждого вложения.

```bash
curl http://localhost:8000/api/deadline/ \
  -F group=261-329 \
  -F date=2026-11-20 \
  -F 'subject=Физика' \
  -F 'deadline=Сдать отчёт' \
  -F 'attachments=@report.pdf' \
  -F 'attachments=@photo.jpg'
```

Тот же формат работает на `POST /api/deadline/confirm/` для нового дедлайна. Если подтверждение с файлами нашло существующую запись, API возвращает `409`. Максимальный размер файла составляет 20 МиБ. Превышение возвращает `413`. Видео и файлы с неподдерживаемыми расширениями возвращают `422`. Поддерживаются распространённые форматы документов, изображений и архивов.

В ответах дедлайна, включая список и расписание, поле `attachments` содержит массив объектов с `name`, `size` в байтах и абсолютным `url`. Для дедлайнов без файлов возвращается пустой массив. По ссылке любой пользователь может скачать файл без входа в систему.

Файлы хранятся в Docker volume `media`. Для ссылок, которые будут использоваться в Telegram или приложении, задайте в `.env` внешний адрес API через `PUBLIC_API_URL` (например, `https://api.example.org`) и разрешите домен через `DJANGO_ALLOWED_HOSTS`. Если перед API стоит прокси, для загрузки всех пяти файлов по 20 МиБ установите лимит тела запроса с запасом, например 105 МиБ.

## Добавление через ИИ

### 1. Распознать текст

`POST /api/deadline/parse/`

```json
{
  "group": "261-329",
  "text": "Сдать отчёт по лабораторной по физике до пятницы"
}
```

DeepSeek извлекает предмет, дату и задание с учётом расписания группы. Если срок не указан, для определения даты используется ближайшее занятие по предмету после текущего дня в пределах 30-дневного окна. Текущий день определяется по московскому времени.

Ответ `200` содержит `group`, `date`, `subject` и `deadline` в формате тела запроса из раздела «Ручное добавление». На этом шаге клиент показывает результат пользователю для подтверждения. Проверка дублей и запись в базу происходят на следующем шаге.

- `422` означает, что требуется уточнить предмет, дату или задание. Отправьте исходный текст с уточнением повторно.
- `503` возвращается при ошибке загрузки расписания или обращения к ИИ, включая отсутствие `AI_KEY` и некорректный ответ провайдера.

### 2. Подтвердить и сохранить

`POST /api/deadline/confirm/` принимает четыре поля из ответа `parse`. Клиент может учесть правки пользователя перед отправкой. Чтобы сохранить файлы при подтверждении нового дедлайна, отправьте эти же четыре поля и файлы в `attachments` как `multipart/form-data`. Дополнительный вызов `POST /api/deadline/` не требуется.

API ищет совпадения по группе, дате и предмету. Точный повтор после нормализации обрабатывается сразу. Если у найденных записей отличается текст задания, DeepSeek определяет, описывают ли они то же задание, и при совпадении объединяет совместимые детали.

```json
{
  "status": "created",
  "deadline": {
    "id": 42,
    "date": "2026-11-20",
    "subject": "Физика",
    "deadline": "Сдать отчёт по лабораторной работе",
    "group": "261-329",
    "attachments": []
  }
}
```

| `status` | Результат |
| --- | --- |
| `created` | Создан новый дедлайн |
| `updated` | Существующий дедлайн дополнен, его ID сохранён |
| `unchanged` | Возвращён существующий дедлайн без изменений |

Если для сравнения нужен ИИ, а вызов завершился ошибкой, запрос возвращает `503` и изменения в базе откатываются.

## Удаление дедлайна

`DELETE /api/deadline/?id=42` принимает целочисленный `id` в строке запроса.

- `200` с телом `{"detail":"Запись удалена"}`, если запись удалена. Вместе с дедлайном удаляются его вложения.
- `404` с телом `{"detail":"Запись не найдена"}`, если записи с таким ID нет.

## Задания на сессию

`GET /api/session-task/?group=261-329&semester=2026-2` возвращает массив предметов за семестр. У каждого предмета есть `subject`, готовый нумерованный список `text` и массив `tasks` с отдельными заданиями, их ID и сроками. Пункты идут в порядке добавления. Если заданий нет, возвращается `[]`.

`POST /api/session-task/` принимает JSON без вложений.

```json
{
  "group": "261-329",
  "semester": "2026-2",
  "subject": "Физика",
  "text": "Сдать отчёты по лабораторным работам",
  "due_date": "2026-12-20"
}
```

Для GET и POST параметр `semester` можно опустить, тогда используется текущий семестр по московскому времени. Формат `YYYY-1` обозначает весенний семестр с февраля по август, `YYYY-2` обозначает осенний семестр с сентября по январь следующего года. При ручном добавлении поле `due_date` можно опустить или передать как `null`. При создании возвращается объект из примера с полем `id`. Точный повтор возвращает `409`.

Для добавления через ИИ отправьте на тот же маршрут номер группы и исходный текст. Семестр можно указать явно.

```json
{
  "group": "261-329",
  "text": "По физике сдать лабораторные 1-4 и защитить курсовую до 20 декабря"
}
```

DeepSeek определяет один предмет по расписанию группы и уже сохранённым предметам семестра. Он разбивает текст на отдельные задания и извлекает явно указанные сроки. API дописывает новые пункты, пропускает точные повторы и возвращает полный список этого предмета в том же формате, что и элемент массива GET. Например, поле `text` содержит `"1. Сдать лабораторные 1-4\n2. Защитить курсовую"`. Если предмет или задания требуют уточнения, API возвращает `422`. При ошибке расписания или DeepSeek возвращается `503`.

`DELETE /api/session-task/?id=42` возвращает `200` с сообщением «Запись удалена» или `404`, если задания с таким ID нет.
